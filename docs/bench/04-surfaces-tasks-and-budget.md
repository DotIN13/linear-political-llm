# 实验计划 ② —— 测哪些下游任务，花多少

图片筛选与对话模板在 **《实验计划 ① — 图片筛选与多轮对话设计》**。

### 选任务的原则：**能用 logprob 就别用解析**，而且要留两个「翻案」任务

模型在本地、是白盒，所以所有离散输出都可以直接取 logprob —— 连续、无天花板、零解析失败。
 阶段④那三个毛病（baseline 顶到 +3.00 ± 0.00、travel 抽取 40/40 全空、二选一排序几乎 null）**全都是测量方式的问题，不是效应不存在**。
 所以任务清单里特意留了 **T5** 和 **T6** ——把阶段④那两个失败的任务用 logprob 重做一遍。
 如果它们这次有效应，**那就把当初的空结果从「没有效应」翻成「测错了」**，这本身是论文里很有力的一段。

## 六个任务，按成本排

### [tasks]
- T1**政治二选一 logprob**免费 · 主力   四道题，每题两个单词选项，指标是 `logP(A) − logP(B)`：   每题三种改写取平均。**连续、无天花板、无解析。**

```
2020 大选     → "Biden"      | "Trump"
更严格控枪     → "Support"    | "Oppose"
医保由谁提供   → "Government" | "Market"
边境执法       → "Increased"  | "Decreased"
```

- T2**非政治二选一（特异性对照）**免费 · 必做   茶/咖啡、猫/狗、海边/山里、早起/晚睡。**如果图像把 T1 和 T2 一起推动，那就不是意识形态效应**，  只是某种笼统的回答偏移。这四道题决定 T1 的结论算不算数 —— 所以它不是可选项。
- T3**探针读出 `s_txt`**免费 · 同一次前向   不是任务，是搭车：最后一个文本位置的探针读数。它给出**中介链**的中间变量 ——  图像分数 → `s_txt` → 政治输出。同时记 `s_img`（三张图同时在场时的整图读数）当操作检查。
- T4**七点量表**便宜   “1 = strongly oppose … 7 = strongly support”，读 `"1"…"7"` 七个数字 token 的 logprob，取期望值。  比二选一细，仍然是一次前向。**好处是给出效应的「几分之一格」量级**，二选一只给方向。
- T5**参议员二选一排序 —— 翻案任务之一**要生成   阶段④这一条几乎是 null（dem_impl 20/20、rep_impl 17/20，Fisher p≈0.23）。  **但那是靠解析叙述文本判断谁被排第一**，而且撞上模型 85% 默认选民主党的底色。  改成直接读两个候选人名字的 logprob，天花板和解析问题一起消失。同样的四场 2026 参议员选举，候选人简介一字不改。
- T6**竞选演讲 ＋ LLM 裁判 —— 头条**要生成 · 有 API 成本   直接搬阶段④的管线，裁判提示词和五个维度**一字不改**，所以新旧结果直接可比。  **它是阶段④唯一被证明没有天花板的测量**（dem_impl 落 +0.2~+0.7、rep_impl 落 −0.6~+0.4，  gap 0.485，五维度全 p < 0.001）。现在换成 Qwen3-VL 看着图写。  `classifiers/senate_speech.py` 原封不动能解析裁判输出。

### 还有一个可选的 T7

- **消费推荐排名 —— 翻案任务之二。**阶段④的 cars / beer / weekend / books 四个域，baseline 全部顶在 +3.00 ± 0.00，  也就是 20 次里 20 次把三个民主党项全排在前面，**dem_profile 那一侧完全没有可动的空间**。
- **改成读六个选项的 logprob 就没有上限了** —— 直接给出六项的连续偏好序，而不是一个被压扁的名次。  清单一字不改，所以能和阶段④逐项对比。
- **为什么放可选：**它是四个域 × 六项，条目数翻好几倍，而它主要是为了「翻案」而不是为了主结论。  **等 T1 有信号之后再决定要不要做。**
- 如果做，它会是论文里最直观的一张图：同一个实验，旧测量顶格、新测量有梯度。

### 要报的不是六个 p 值

六个任务不是六个独立结论。**要报的是一条链**：
 图像分数 → `s_txt` → 政治输出，以及控制 `s_txt` 之后图像的直接效应还剩多少。

T1 是主要结果，T2 决定它算不算数，T3 是中间变量，T4 给量级，
 T5/T6 一个翻案一个当头条。**把它们写成六个小节是最容易犯的错。**

## 三次运行，每次有明确的产出和判断

### [runs]
- R1**框架对比（半天）。**300 个条目 × 五个框架变体（A–E）× 八道题（T1＋T2）＝ **12000** 次前向。  **产出：哪个框架承载效应，以及「归属」是不是必要条件**（A 无效应而 C 有效应就说明是）。**拿这个定后面用哪个框架。**12k prefill ≈2 小时 · 1×H200
- R2**主实验（一天）。**探索集 2000 个条目（每条 3 图，共 6000 张）× 八道题 × 三种改写 ＝ **48000** 次前向，  加 T4 量表。**产出：剂量反应曲线 ＋ 安慰剂方向 ＋ 中介。**确认集先不动。48k prefill ≈半天 · 1×H200
- R3**生成层（半天）。**600 个条目 × T5 ＋ T6：600 段演讲（约 350 token）＋ 600 次裁判调用。  **产出：可以和阶段④直接对比的那个数。**600 生成 ＋600 次 API ≈ 几美元
- R4**确认集（一次，别偷看）。**口径在 R2 上定死之后，把确认集的 2000 个条目按同一套代码跑一遍。  **这一次的结果就是论文里的数。**48k prefill ≈半天

### 让它跑得快的两件事

- **复用对话前缀的 KV cache。**八道题共用完全相同的前缀（三张图 ＋ 四个写死的回合）。缓存一次，  **能省掉八分之七的图像编码** —— 图像 token 上千，这是主要成本。
- **批处理按 `num_image_tokens` 分桶。**不同图的视觉 token 数从 300 到 800，混在一批里 padding 浪费很大。  CSV 里那一列现成，按它排序分桶就行。
- 这两条做完，48000 次前向在 H200 上是小时级而不是天级。不做也能跑，只是慢。

### 有两个只能你拍的决定

**① 三图还是一图？**我倾向三图 —— 阶段④给的是六件物品，一图等于 1/6 剂量，效应小的话很可能测不到。
 但三图让「是哪张图起作用」变得不可分，而且条目数除以三。**R1 里 C（三图）和 D（一图）是拆开的，所以这个决定可以推到 R1 之后**，
 我建议就这么办。

**② T6 演讲要不要在 R1 就加进去？**它是唯一被证明有效的测量，早点看到它有没有反应很有价值；但它要生成、要调 API，会把 R1 从半天拖成一天。
 **我的建议是 R1 只跑 T1＋T2**（纯 prefill，最快拿到「有没有信号」），T6 放 R3。
 除非你想尽早拿一个能给别人看的结果 —— 那就在 R1 里塞 100 个条目的 T6 当预览。
